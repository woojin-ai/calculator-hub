## 1. OG 태그 부재가 실제로 어떤 손실인지 — 채널별

### 1-0. 먼저, 오늘까지의 손실은 사실상 0이다

정직하게 말하면 **지금 이 순간까지 OG 부재로 잃은 트래픽은 0에 가깝다.**

- 2026-07-20 감사에서 `marketing/` 전량(promo-drafts 1030줄 + 카드뉴스)을 조사해 **밖으로 나간 링크가 0건**임이 확인됐다(`docs/team-log/2026-07-20-gsc-audit.md:44`).
- 카드뉴스 9편은 전부 초안 상태이고, SNS 게시는 한 번도 없었다.
- 공유가 0이면 링크 프리뷰가 렌더될 기회 자체가 0이다.

**즉 OG 부재는 "이미 발생한 손실"이 아니라 "게시 개시 순간 켜지는 손실"이다.** 이 구분이 우선순위 판단의 핵심이라 §4에서 다시 쓴다.

정량 추정은 하지 않는다 — GA/GA4 미도입, GSC API 자격증명 부재(12일째)로 **레퍼러 기반 유입 측정 수단이 현재 0개**다. "OG 넣으면 CTR 몇 % 상승" 같은 숫자는 근거가 없어 쓰지 않는다. **[미확인]**

### 1-1. 카카오톡 — 손실이 가장 큰 채널

한국 시장에서 계산기 링크의 실제 확산 경로는 "SNS 게시물"이 아니라 **"본 사람이 단톡방에 붙여넣는 것"**이다. 연봉·퇴직금·주휴수당 계산기는 성격상 회사 단톡방·알바 단톡방에서 2차 확산될 여지가 큰 소재다. 이 경로에서 프리뷰가 없으면 확산이 직접 깎인다.

- **[공식]** 카카오 개발자 포럼(데브톡) 스크랩 FAQ: **"og 태그가 있어야 미리보기가 됩니다."** 그 외 요건은 200 응답 / 80·443 포트만 허용 / content-type `text/html`.
- **[2차]** OG가 없으면 카카오톡에서 **제목도 이미지도 없이 파란 하이퍼링크 텍스트만** 표시되거나, 크롤러가 본문에서 임의 추출한 불완전한 텍스트/이미지가 노출된다.
- **[공식/스니펫]** 카카오 메시지 템플릿 문서상 스크랩은 `<head>`의 `og:title`·`og:image`·`og:description`으로 피드형 메시지를 구성하고, `og:site_name`은 "확인 from ${SCRAP_HOST}" 형태로 노출된다. *(문서 원문 직독은 실패 — `developers.kakao.com/docs/latest/ko/message/scrap`이 302 후 404. 검색 스니펫 기반이라 반쪽 근거로 표기)*
- 손실 형태: **"계산기 허브 | 주휴수당 계산기" 라는 신뢰 신호가 통째로 사라지고, 링크가 스팸/피싱처럼 보인다.** 금융·급여 소재라 이 인상 손실은 일반 콘텐츠보다 더 아프다.
- **[미확인]** 사용자가 채팅방에 **직접 붙여넣는** 경로에도 앱 도메인 사전등록이 필요한지. (도메인 등록은 SDK `sendScrap` API 문서에 나오는 요건이고, 데브톡 체크리스트에는 등록 요건이 없다. 붙여넣기 경로는 불필요할 가능성이 높아 보이나 확인 못 함.)
- 리포 확인: 사이트에 카카오 공유 버튼·SDK는 없다. 따라서 공유는 100% 수동 붙여넣기 경로다.

### 1-2. 인스타그램 — 손실이 생각보다 작다 (표면별로 갈림)

인스타는 **표면(surface)마다 동작이 완전히 다르다.** 이걸 뭉뚱그리면 판단을 틀린다.

| 인스타 표면 | 링크 프리뷰 | OG 영향 |
|---|---|---|
| **피드 게시물 캡션** | **[2차]** 링크가 클릭조차 안 되고 **프리뷰도 생성되지 않음** (평문 텍스트) | **영향 0** |
| **프로필 바이오 링크** | 탭하면 인앱 브라우저로 바로 이동 — 프리뷰 개념 없음 | **영향 0** |
| **스토리 링크 스티커** | **[2차]** 크롤러가 OG를 읽어 썸네일을 만들고, `og:image`를 **정사각 중앙 크롭**으로 표시 | **`og:image`가 있어야 실효. 텍스트 OG만으론 거의 0** |
| **DM** | **[2차]** OG 기반 프리뷰 카드 생성 | `og:image` 위주 |

- **[2차]** 인스타는 메타 소유라 페이스북과 같은 스크래핑 인프라·같은 OG 태그를 쓴다.
- 마케팅 결론: **카드뉴스 본편(피드 캐러셀)에는 OG가 아무 일도 하지 않는다.** 인스타에서 OG가 일하는 곳은 **스토리 링크 스티커와 DM뿐**이고, 둘 다 이미지가 핵심이다.

### 1-3. 페이스북 / 스레드

- **[공식]** 메타 공식 문서(`developers.facebook.com/docs/sharing/webmasters/`) 원문: **"Without these Open Graph tags, the Facebook Crawler uses internal heuristics to make a best guess about the title, description, and preview image for your content."**
  - 즉 페북에서는 프리뷰가 **아예 안 뜨는 게 아니라, 크롤러가 "추측"한다.** 문서는 최소 필수 태그를 명시하지 않고 `og:url`/`og:title`/`og:description`/`og:image` 4종을 권장하며, 추측에 맡기지 말라고 한다.
  - **[미확인]** 추측이 구체적으로 `<title>`·`meta description`을 쓰는지는 공식 문서에 명시가 없다. 우리 사이트는 62개 전 페이지에 title/description이 이미 있으므로(GSC 감사 기왕 확인) 추측 결과가 그럭저럭 나올 수도 있고, 계산기 UI 텍스트를 긁어 엉뚱하게 나올 수도 있다. **어느 쪽인지 모른다.**
- **스레드**: **[2차]** OG 프로토콜을 준수하며 `og:image`로 프리뷰 카드를 만든다. 공식 문서 원문은 확인 못 함 **[미확인]**.
- **여기가 실무상 진짜 트리거다.** 카드뉴스 초안 9편에는 **전부 "스레드(짧게)" 캡션이 들어 있다**(리포 확인: `marketing/card-news/weekly-holiday-allowance-extra-hour-2026.md` §SNS 캡션 2). 스레드는 인스타와 달리 **본문 URL이 클릭 가능**하다. 스레드 캡션에 URL을 직접 넣는 순간부터 OG 부재가 즉시 실손실로 바뀐다.
  - 참고로 현재 스레드 초안들은 CTA를 "→ 프로필 링크"로 쓰고 있다. 이건 인스타 관습을 스레드에 그대로 옮긴 것이고, **스레드에서는 URL 직접 삽입이 유입상 유리하다.** 이 문구 개선은 OG 도입과 세트로 다뤄야 한다.

### 1-4. X (트위터)

X는 다른 플랫폼과 판단이 **정반대**다. 여기서는 OG를 넣어도 이미지가 없으면 거의 아무것도 얻지 못한다.

- **[2차/매체]** 타임라인: 2023-08 머스크가 헤드라인 제거 예고 → **2023-10-04 실제 적용**(카드에서 헤드라인·설명 제거, **이미지 + 도메인 오버레이만** 표시) → 2023-11 "이미지 상단에 제목 오버레이하겠다" 발표 → **2024-01-02 잠깐 부활했다가 몇 시간 만에 롤백**. 롤백 시점 기준 안드로이드만 구식 헤드라인, iOS·웹은 헤드라인 없음.
- **[미확인]** **2026-07 현재 X의 링크 카드 렌더 상태.** 2024-01 이후의 변경 이력을 확인할 신뢰 출처를 찾지 못했다. 아래 판단은 "이미지 중심 카드"라는 2024-01 상태를 전제로 한다.
- **[2차]** X는 `twitter:` 태그가 없으면 대응되는 `og:` 태그로 폴백한다(`og:title`/`og:description`/`og:image`). 따라서 **`twitter:` 태그 없음 자체는 큰 문제가 아니다.**
- **[2차]** 이미지가 없거나 로드 실패하면 카드가 뜨지 않고 **평문 URL**로 표시된다.
- 결론: X에서 OG의 효용은 사실상 **`og:image` 하나에 달려 있다.** 텍스트 OG만 넣으면 X 노출은 거의 개선되지 않는다.
- **[2차]** 캐시: X가 과거 7일 캐시 윈도우를 문서화했으나 현재 윈도우는 명확히 문서화돼 있지 않다(theseoframework KB, 2026-05-17 게재).

### 1-5. 커뮤니티 / 네이버

- **[2차]** 네이버 블로그·카페는 입력창의 문자열이 링크임을 인식하면 크롤러로 `<head>`의 OG를 긁어 `og:title`·`og:description`·`og:image`로 미리보기를 만든다.
- 커뮤니티(디시·클리앙·뽐뿌 등) 개별 사이트의 링크 프리뷰 동작은 **[미확인]** — 사이트마다 구현이 제각각이라 일반화하지 않는다. 다수는 프리뷰 자체가 없고 평문 링크다(이 경우 OG 영향 0).

## 2. 카드뉴스 게시 전에 OG가 "반드시" 있어야 하는가 — 정직한 판단

### 결론: **아니다. OG는 카드뉴스 게시의 blocker가 아니다.**

이건 팀로그가 07-20부터 07-26까지 7일 연속 "첫 SNS 게시 승인 전 처리 권장"이라고 반복해 온 것에 대한 **정정 제안**이다. 그 표현은 절반만 맞다.

**blocker가 아닌 이유:**
1. 카드뉴스 본편은 **인스타 피드 캐러셀(이미지 게시물)**이다. 링크가 개입하지 않는다.
2. CTA가 "프로필 링크"다 — 리포 확인 결과 현재 카드뉴스 9편의 CTA는 전부 프로필(바이오) 링크 방식이다(07-20 감사도 동일 결론). **바이오 링크는 프리뷰를 렌더하지 않는다.**
3. **[2차]** 인스타 캡션의 URL은 클릭도 안 되고 프리뷰도 안 만든다. 캡션에 URL을 써도 OG는 호출되지 않는다.
4. `.env.local`의 `IG_BUSINESS_ACCOUNT_ID`/`IG_ACCESS_TOKEN`을 쓰는 Graph API 게시 경로도 마찬가지다 — 이미지 업로드 + 캡션 게시이고, **OG는 이 파이프라인에 관여하지 않는다.**

**그럼에도 게시 전에 처리해야 하는 이유(= blocker는 아니지만 선행 과제인 이유):**

1. **캐시 때문에 순서가 되돌릴 수 없다.** 카카오·페북·X 모두 스크랩 결과를 캐시한다. **[공식]** 카카오 데브톡은 문제 시 "캐시를 초기화하고 다시 시도"를 해법으로 제시하며, 유지 기간은 명시하지 않는다 **[미확인]**. X 캐시 윈도우도 현재 불명확 **[미확인]**. 즉 **"먼저 게시하고 나중에 OG를 넣으면", 초기 게시물에서 파생된 프리뷰는 상당 기간 깨진 채 남는다.** 초기 확산분이 가장 아까운 시점인데 그게 손상된다. 되돌리려면 플랫폼별 캐시 초기화를 일일이 해야 한다.
2. **카드뉴스와 동시에 나가는 텍스트 채널이 이미 초안에 있다.** 스레드 캡션 9편이 그것이다(§1-3). 스레드에 URL을 넣는 순간 OG 부재는 즉시 실손실이다.
3. **2차 확산은 통제 불가다.** 카드뉴스를 본 사람이 계산기 URL을 단톡방에 옮기는 순간이 실질적 최대 유입 경로인데(§1-1), 그 시점을 우리가 고를 수 없다.

**정리:** OG는 *카드뉴스 승인을 막을 사유가 아니다*(막으면 13일째 대기가 더 길어질 뿐이다). 대신 **카드뉴스 승인과 병렬로, 첫 게시가 나가기 전까지 텍스트 OG를 끝내 두는 것**이 맞다. 두 작업은 서로 의존 관계가 없다.

## 3. `og:image` 없는 OG(title/description/url/type)는 아예 없는 것보다 나은가

### 결론: **플랫폼별로 갈리지만, 종합하면 "그렇다". 특히 한국 채널에서 명확히 낫다.**

| 플랫폼 | 이미지 없는 OG의 렌더 (추정 근거) | 없는 것보다 나은가 |
|---|---|---|
| 카카오톡 | **[미확인]** — 카카오가 `og:image` 없이 텍스트만으로 카드를 그리는지, 아예 프리뷰를 포기하는지 원문 확인 실패. 데브톡은 "og 태그가 있어야 미리보기가 된다"고만 함 | **개선 가능성 높음(확정 아님).** 현 상태(파란 링크 텍스트)보다 나빠질 경로는 없음 |
| 페이스북 | **[공식]** OG가 없으면 "internal heuristics로 best guess". OG를 주면 **추측이 제거되고 제목·설명이 우리 통제 하에 들어옴** | **명확히 낫다** (이미지 없는 작은 카드 vs 통제 불가 추측) |
| 스레드 | **[2차]** OG 준수. 이미지 없는 카드 형태는 **[미확인]** | 낫다(정도는 미확인) |
| 네이버 블로그/카페 | **[2차]** `og:title`·`og:description` 사용 | **명확히 낫다** |
| X | **[2차]** 이미지 없으면 카드 미표시, 평문 URL | **차이 거의 없음**(나빠지지도 않음) |
| 인스타 스토리 스티커 | **[2차]** 이미지가 핵심, 이미지 없으면 프리뷰를 건너뛸 수 있음 | **차이 거의 없음** |

**판단:** 이미지 없는 OG가 **어떤 플랫폼에서도 현 상태보다 나빠지지 않고**, 카카오·페북·네이버에서는 개선되며, 개선 폭이 가장 큰 카카오가 우리 주력 소재(급여/대출)의 실제 확산 경로다. **부분 도입은 "반쪽"이 아니라 "가치 있는 절반"이다.**

### 07-20 분리 사유에 대한 사실 갱신 (중요)

07-20 감사가 OG를 canonical과 묶지 않은 근거 두 가지는 **오늘 기준 사실관계가 달라졌다.** 재검토가 필요하다.

1. **"og:image 에셋이 존재하지 않는다"** → **더 이상 사실이 아니다.** 리포 확인:
   - `public/images/hero-illustration.webp` — **이미 홈(`app/page.tsx:65`)에 라이브로 노출 중인 브랜드 이미지.** 신규 생성이 아니므로 "이미지 생성 사용자 승인" 게이트에 걸리지 않을 여지가 있다(최종 판단은 마스터·사용자 몫).
   - `public/images/card-news/bmi-weight-change-sensitivity-2026/card-1.png` ~ `card-8.png` — **BMI 카드뉴스 8장이 이미 커밋돼 있다.**
   - `public/images/icons/{salary,loan,date,life}.webp` — 카테고리 아이콘 4종.
   - **[미확인]** 이 자산들의 실제 픽셀 크기·종횡비가 권장 규격(1200×630)에 맞는지. 코드 수정 금지 범위라 확인하지 않았다.
   - **[미확인]** 커밋된 카드뉴스 PNG가 라이브 URL에서 200으로 서빙되는지 직접 확인(HTTP 프로브 수단 없음). `public/` 배치이므로 경로상 존재는 확실.
2. **"`metadataBase` 도입은 URL 조립을 두 갈래로 만든다"** → **`metadataBase` 없이도 된다.** 리포 확인: `lib/site.ts`에 이미 `SITE_URL` + `canonicalUrl(path)`가 있고 25개 라우트가 이걸로 절대 canonical을 만들고 있다. `og:url`/`og:image`에 같은 헬퍼를 쓰면 **URL 조립 갈래는 늘지 않고 그대로 1개**다. 07-20의 반대 의견(기획팀 §4)이 겨냥한 리스크가 제거된 셈이다.
   - 단, 이건 마케팅팀의 관찰이지 구현 결정이 아니다. **실제 구현 방식은 design→dev 판단 사항.**

## 4. 우선순위 권고

### [A] 지금 당장 처리 — 텍스트 OG (`og:title`/`og:description`/`og:url`/`og:type`/`og:site_name`/`og:locale`)

- **사용자 승인 불필요**(신규 이미지 자산 0개), **신규 에셋 0개**, `canonicalUrl()` 재사용으로 URL 조립 갈래 증가 0.
- 카카오·페북·네이버에서 즉시 이득, 나머지 플랫폼에서 손해 0.
- **캐시 비가역성**(§2) 때문에 첫 게시 이후로 미루면 초기 확산분이 손상된다. 게시 일정과 무관하게 지금 끝내는 게 순비용이 가장 싸다.
- 덤: `twitter:card`(`summary` 또는 이미지 도입 후 `summary_large_image`) 한 줄은 비용이 사실상 0이라 같이 넣어도 무방하나, X는 og 폴백을 쓰므로 **없어도 치명적이지 않다.**

### [B] 카드뉴스 게시 승인 시점에 처리 — `og:image`

- 카드뉴스 이미지화 승인이 나면 **같은 승인 안에서 og:image 자산도 함께 확정**하는 게 효율적이다(승인 왕복 1회 절약).
- **선택지 1(승인 부담 최소):** 이미 라이브인 `hero-illustration.webp`를 사이트 전역 기본 og:image로. 신규 생성 없음.
- **선택지 2(효과 최대):** 계산기 카테고리별 4종(salary/loan/date/life 아이콘 활용) 또는 페이지별 자동 생성 OG 이미지. **신규 제작 = 도구 사용 승인 필요 → 마스터 보고 대상.**
- 규격 적합성(1200×630)은 **[미확인]** — design팀이 확인해야 한다.
- 이 단계가 완료돼야 **인스타 스토리 링크 스티커**와 **X 카드**가 비로소 의미를 갖는다.

### [C] 낮음

- `twitter:` 전용 태그 풀세트(`twitter:title`/`twitter:description`/`twitter:image`) — og 폴백으로 대체되므로 중복 투자.
- `og:image:width`/`height`/`alt`, `article:published_time` 등 부가 태그 — 있으면 좋지만 유입 기여는 미미.
- 커뮤니티 사이트별 프리뷰 최적화 — 동작이 제각각이고 **[미확인]**이라 투자 근거가 없다.

### 함께 처리 권고 (마케팅팀 자체 과제, 코드 무관)

- **스레드 캡션의 CTA 문구 교체**: 현재 9편 전부 "→ 프로필 링크"인데, 스레드는 본문 URL이 클릭 가능하다. **URL 직접 삽입 방식으로 바꾸는 것이 유입상 유리**하며, 이 변경은 [A] 완료를 전제로 한다. (초안 수정은 별도 슬롯에서 — 이 문서는 진단만.)
