## 0. 이 문서의 범위

기획팀은 **"근속기간 N년 M개월 D일"이 무엇을 뜻하는가**를 확정한다.
코드 수정·테스트 작성은 개발팀/QA팀 몫이다. 아래 §2의 참조식은 구현 지시가 아니라
"이 값이 나와야 한다"는 정의를 식으로 옮긴 것이다.

**어제 스펙 §3-4-1의 재현조건은 폐기한다.** 그 조건은 `종료일 = 월말`이라는 스코프가
암묵적으로 걸려 있어 실제 결함 집합보다 좁다(반례: `2000-01-31 → 2026-03-01`은
종료일이 월말이 아닌데 결함 발생). 앞으로는 §1의 일반식만 인용할 것.

## 1. 결함의 일반식과 전수 분류 (손 추적)

### 1-1. 일반식

기호: `S` = 입사일, `E` = 종료일, `E⁺` = 종료일 + 1일(코드의 `endPlus`),
`L_prev` = `E⁺` **직전 달**의 실제 일수.

```
결함 발생 ⟺ (E⁺의 일 − S의 일) + L_prev < 0
```

이 식의 좌변이 곧 현재 코드가 1회 차용을 마친 뒤의 `days` 값이다.
즉 **"결함 발생" = "`days < 0`"** 이고, 등가 조건이므로 누락·과다 없이 정확하다.

### 1-2. 결함 집합은 유한하며 전부 2월에서만 발생한다 (손 추적)

일반식을 풀면:

- `E⁺의 일 ≥ 1` 이므로 결함 조건은 `S의 일 − L_prev ≥ 2` 를 필요로 한다.
- `S의 일 ≤ 31` 이므로 `L_prev ≤ 29`.
- 달력상 `L_prev ≤ 29`인 달은 **2월뿐**이다.

따라서 **`E⁺`가 3월인 경우, 즉 종료일이 2월 말일 또는 3월 1일인 경우에만** 결함이 난다.
전수 분류(연 단위):

| 분류 | 해 | S의 일 | 종료일 E | E⁺의 일 | 현재 days |
|---|---|---|---|---|---|
| (i) | 평년 | 30 | 2월 28일 | 1 | **−1** |
| (ii) | 평년 | 31 | 2월 28일 | 1 | **−2** |
| (iii) | 평년 | 31 | 3월 1일 | 2 | **−1** |
| (iv) | 윤년 | 31 | 2월 29일 | 1 | **−1** |

- 윤년에 `S의 일 = 30`은 `30 − 29 = 1 < 2`라 결함 아님.
- 윤년에 `S의 일 = 31`, 종료일 3월 1일은 `2 − 31 + 29 = 0`이라 결함 아님.

**검산:** 브루트포스 범위(2019~2031, 13년)는 윤년 3개(2020·2024·2028) + 평년 10개.
`10 × 3(i·ii·iii) + 3 × 1(iv) = 33`. 마스터가 실측한 **33건과 정확히 일치**한다.
→ 결함 집합은 완전히 열거 가능하며, QA는 이 4개 클래스만 검증하면 전수 커버된다.

### 1-3. 보고된 재현 2건의 소속

- `2000-01-31 → 2026-03-01` = 분류 (iii). 현재 `26년 1개월 −1일`.
- `2020-01-31 → 2021-02-28` = 분류 (ii). 현재 `1년 1개월 −2일`.

## 2. (1) 올바른 차용 시맨틱 — 결정

### 2-1. 후보는 둘이 아니라 셋이다

마스터가 제시한 (A)/(B) 중 **(B)는 두 갈래로 갈리며 둘의 답이 다르다.** 따라서 실제
선택지는 세 개다.

| 안 | 정의 | 요약 |
|---|---|---|
| **(A)** | 음수가 사라질 때까지 직전 달을 계속 빌린다 | 잔여일 우선 |
| **(B-1)** | months를 먼저 1 줄이고, `S + months개월`(**앵커 clamp**)에서 실제 경과일을 센다. java.time `Period.between` / dateutil `relativedelta` 방식 | 앵커를 말일로 당김 |
| **(B-2)** | months를 먼저 1 줄이고, **민법 제160조 제3항(최종 월에 해당일이 없으면 그 월의 말일로 만료)** 을 적용해 월 경계를 잡은 뒤 잔여일을 센다 | 만료일을 말일로 밂 |

### 2-2. 세 안이 갈리는 구체 사례 (손 추적)

**사례 α — 입사 2000-01-31 / 종료 2026-03-01** (분류 iii)

| 안 | 결과 | 손 추적 |
|---|---|---|
| 현재(버그) | `26년 1개월 −1일` | days = 2 − 31 + 28(2026년 2월) = −1 |
| (A) | `26년 0개월 30일` | 2차 차용: 2026년 1월 31일 → days = −1 + 31 = 30, months 0 |
| (B-1) | `26년 1개월 2일` | 앵커 = 2000-01-31 + 313개월 = 2026-02-31 → clamp 2026-02-28. 2026-03-02 − 2026-02-28 = 2 |
| (B-2) | `26년 1개월 1일` | 26년 1개월 만료일 = 2026년 2월 "31일" 없음 → 2월 말일(28일) 만료. 경계 = 2026-03-01. 2026-03-02 − 2026-03-01 = 1 |

세 안이 전부 다른 답을 낸다. **(A)와 (B)가 다른 답을 내는 사례는 존재한다.**

| (A) | `0년 0개월 29일` |

| (B-2) | `0년 1개월 0일` |

**사례 γ — 입사 2020-01-31 / 종료 2021-02-28** (보고된 재현 2)

| 안 | 결과 |

γ는 **(A)와 (B-1)이 같은 답을 내는 사례**다. 즉 "A와 B는 항상 다르다"도 틀렸고

### 2-3. 결정 — **(B-2) 채택**

#### 근거 ①: 민법 제160조 제3항이 이 문제를 직접 규정한다

기간을 월·년으로 정한 경우의 계산은 민법 제160조를 따른다.

- 제160조 제2항: 최후의 월/년에서 **기산일에 해당한 날의 전일**로 기간이 만료한다.
- 제160조 제3항: **최종의 월에 해당일이 없는 때에는 그 월의 말일로 기간이 만료한다.**

계속근로기간은 입사일을 산입(초일산입)해 기산하고, 퇴직일(= 마지막 근무일의 다음 날)까지를
센다. 이 사이트의 `종료일⁺ = 종료일 + 1일` 규약이 정확히 이 "퇴직일" 개념과 맞물린다.

따라서 **1월 31일 입사자의 "1개월"은 2월에 31일이 없으므로 2월 말일에 만료한다.**
1월 31일 입사 → 2월 28일 근무는 **"1개월"이 맞다.** ("28일"도 "29일"도 아니다.)
사례 β의 답 `0년 1개월 0일`이 이것이다.

#### 근거 ②: (A)는 제도 판단을 반대 방향으로 오도한다

근로기준법 제60조 제2항은 계속근로 1년 미만 근로자에게 **1개월 개근 시 1일**의 유급휴가를
정한다. 1월 31일 입사자가 2월 28일까지 개근한 시점에서 (A)는 화면에 `0개월 29일`을
띄운다. 사용자는 "아직 1개월이 안 됐다"고 읽게 된다. 이 계산기는 퇴직금·연차 계산기의
전단 진입점(`relatedSlugs`에 severance / annual-leave가 물려 있음)이므로, 월 경계를
한 칸 적게 세는 오류는 그대로 하류 판단으로 전파된다. **YMYL 리스크가 (A) 쪽이 크다.**

#### 근거 ③: (B-1)은 발행된 블로그 본문을 깨뜨린다 — 결정적 배제 사유

`service-period-milestone-2026`(2026-07-19 발행)은 **"만근일 = 근속기간이 정확히
`N년 0개월 0일`로 표시되는 종료일"** 이라는 정의 위에 조견표 전체가 서 있다.

(B-1)을 채택하면 **2월 29일 입사자에 대해 `N년 0개월 0일`이 아예 존재하지 않는다.**
(손 추적)

- `Period.between(2024-02-29, 2025-02-28)` → 앵커 clamp 발동 → `0년 11개월 30일`
- `Period.between(2024-02-29, 2025-03-01)` → `1년 0개월 1일`

즉 `1년 0개월 0일`을 만드는 종료일이 없다. 조견표의 `2024-02-29 입사 → 1년 2025-02-28`
행이 라이브에서 재현 불가능해지고, 본문 "둘째, 2월 29일 입사자의 1년 만근일은
'존재하지 않는 날짜'가 되지 않습니다" 문단이 통째로 거짓이 된다.

(B-2)는 같은 입력에서 `1년 0개월 0일`을 그대로 유지한다(§3-2 확인).

#### 근거 ④: (A)에는 구현 함정이 하나 더 있다

`if` → `while` 로 한 글자만 바꾸면 **차용 대상 달이 갱신되지 않아 같은 2월을 두 번 빌린다.**
사례 α에서 그 결과는 `26년 0개월 27일`로, (A)의 의도값(`0개월 30일`)과도 다른 **제3의
오답**이다. "if를 while로 바꾸면 된다"는 처방을 그대로 개발팀에 넘기면 안 된다.

### 2-4. 확정 시맨틱 (개발팀 인계용 정의)

> **정의.** `근속기간 = (years, months, days)`는 다음을 만족하는 유일한 값이다.
> `n = years × 12 + months`라 할 때, `n`은 `boundary(n) ≤ 종료일⁺`를 만족하는 최대 정수이고,
> `days = 종료일⁺ − boundary(n)` (일수차)이다.
>
> **`boundary(n)` (= 입사일부터 n개월이 만료한 다음 날):**
> 대상 달 = 입사일의 (연, 월)에 n개월을 더한 달, `L` = 대상 달의 일수라 할 때
> - `입사일의 일 ≤ L` → `boundary(n) = 대상 달의 (입사일의 일)`   (응당일 존재)
> - `입사일의 일 > L` → `boundary(n) = 대상 달 다음 달의 1일`   (민법 §160③: 말일 만료 → 그 다음 날)

**참조 구현식(개발팀 판단으로 대체 가능).** 기존 코드의 `if (days < 0)` 블록 한 곳만
분기하면 된다. `L_prev` = 종료일⁺ 직전 달 일수, `S_d` = 입사일의 일, `E⁺_d` = 종료일⁺의 일:

```
months -= 1
days = (S_d <= L_prev) ? (E⁺_d - S_d + L_prev)   // 응당일 존재 → 기존 계산과 동일
                       : (E⁺_d - 1)              // 응당일 없음 → 민법 §160③
```

`years`/`months` 산출 경로는 **현재 코드와 완전히 동일하게 유지된다**(§3-1 참조).

| INV-12 | **단조성.** 입사일 고정, 종료일을 하루 늘리면 `(years, months, days)`는 사전식으로 정확히 한 단계 증가한다. 즉 `days+1` 이거나, `days=0`으로 리셋되며 `months+1` 이거나, `days=0 && months=0`으로 리셋되며 `years+1` — 셋 중 하나. (건너뜀·되돌아감 0건) |
| INV-13 | **순서 보존.** `E1 <= E2` ⟹ `tuple(E1) <= tuple(E2)` (사전식) |
| INV-14 | **만근일 존재·유일성.** 임의의 입사일 `S`와 임의의 `n >= 1`에 대해, `근속기간 = n년 0개월 0일`이 되는 종료일이 **정확히 하나** 존재한다. → **(B-1)을 기계적으로 걸러내는 불변식.** `service-period-milestone-2026` 본문 전제와 직결 |
| INV-15 | **응당일 규칙.** 종료일 = (입사 응당일 − 1일)이면 `N년 0개월 0일`. 응당일이 그 달에 없으면(2/29 입사자의 평년, 31일 입사자의 30일·2월) **그 달 말일**이 만근일 |
| INV-16 | **같은 날 입·퇴사** → `0년 0개월 1일`, `totalDays = 1` (앵커 E 유지) |
| INV-17 | 계약 불변: `종료일 < 입사일` → `ok:false / end-before-start`, 파싱 실패 → `invalid-start` / `invalid-end` (기존 유지) |

## 4. (3) 회귀 영향 범위 — 실측 결과

### 4-1. 판정 원리

(B-2)가 현재 코드와 값이 달라지는 입력은 **`days < 0`인 입력과 정확히 일치**한다.

- `S의 일 <= L_prev`(응당일 존재)인 경우 → 참조식의 위쪽 분기 = 현재 코드와 동일 식.
  이때 `S의 일 <= 28 <= L_prev`가 항상 성립하는 구간이므로 `days >= 1`, 결함도 없음.
- `S의 일 > L_prev`(응당일 없음)인 경우 → 차이 = `S의 일 − L_prev − 1`.
  이 값이 0이면 값 동일(결함도 없음), 1 이상이면 값이 바뀌는데 그게 곧 §1-2의 (i)~(iv).
