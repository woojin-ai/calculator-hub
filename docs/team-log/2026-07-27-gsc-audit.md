## 2. ★측정 오류를 지시 전에 잡았다 — desc>160 "3건"은 오탐
1차 감사에서 **desc >160자 3건(max 177)** 이 나왔다. 어제 0건이었으므로 회귀로 보였고 dev-team에 지시하기 직전이었다.

**원인**: 해당 description들이 `&#x27;`(작은따옴표) HTML 엔티티를 포함하는데, 내 파서가 **원시 HTML 속성값 길이**를 셌다. `&#x27;` 1개는 raw 6자 / 디코딩 후 1자라 엔티티 6개면 30자가 부풀려진다.

| URL | raw | 디코딩 후 |
| --- | --- | --- |
| `/blog/service-period-guide-2026` | 177 | **147** |
| `/blog/severance-pay-guide-2026` | 164 | **154** |
| `/blog/loan-prepayment-break-even-2026` | 161 | **151** |

`html.unescape` 적용 후 **desc>160 = 0건(max 159), title>60 = 0건(max 59)** — 어제 상태 그대로, **회귀 없음**. 엔티티 보유 페이지는 62개 중 11개다.

→ **표준 확립(신규)**: 메타 태그 길이는 **`html.unescape()` 후 python `len()`** 으로 잰다. 검색엔진은 디코딩된 문자를 센다. 이건 07-25·07-26의 `innerText` 오진과 **같은 계열의 실수**(측정 대상과 측정 도구의 표현 차이)이며, 3일 연속 같은 함정에 걸렸다. 다행히 이번엔 **지시 전에** 잡았다.

### 4-3. ★사양 미확인 1 확정 — Next.js **문서가 틀렸다**
문서 `generate-metadata.md:428`은 *"metadataBase 없이 상대경로를 쓰면 **빌드 에러**"*라고 적혀 있으나, **Next 16.2.10 실제 구현은 에러가 아니라 폴백 + 경고**다.

dev가 통제 실험(임시로 metadataBase 제거 + `/about`에 상대경로 og:image 추가 → 클린빌드 → 원상복구)으로 확인:
```
⚠ metadataBase property in metadata export is not set for resolving social open graph
  or twitter images, using "http://localhost:3000".
```
빌드는 **성공**했고 산출 HTML에 `og:image content="http://localhost:3000/..."`가 **그대로 박혔다.** QA가 소스 수정 없이 `node_modules/next@16.2.10` 모듈을 직접 호출해 **독립 재현**(3케이스: 상대+base없음 → localhost 폴백 / 상대+base있음 → 정상 / 절대+base없음 → 그대로)에 성공했다.

→ **즉 metadataBase 1줄이 없었다면, 2단계에서 이미지를 붙이는 순간 에러도 경고도 없이 `localhost` URL이 라이브에 나갔을 것이다.** 이번 1줄의 실질 가치가 여기 있다.
→ dev의 **정직한 부기**: 이 경고는 상대경로 이미지가 있을 때만 발동하므로, 현 1단계에서 "경고 없음"을 metadataBase 덕분이라 해석하면 과대평가다. 이 자기 정정을 그대로 채택한다.

## 7. 🔴 신규 발견 — 공개 저장소 시크릿 유출 위험 (티켓 #6, 사용자 결정 필요)
QA 관찰 1을 추적하다 발견했다. **이번 실행에서 가장 중요한 발견이다.**

| 사실 | 확인 방법 |
