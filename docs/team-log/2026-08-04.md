### ★마스터 브리프의 사실 오류를 dev가 정정했다
브리프에 부동소수 함정 예시로 `3/30 → 10.000000000000002`를 적었는데, **dev가 실측으로 반증**했다(`3/30 === 0.1`, `0.1*100 === 10`). 다만 **결론(정수 산술로 판정하라)은 유효**했고, dev가 D≤36 전 조합을 실측해 **진짜 함정 3건**을 찾아냈다:

`11/20 → 55.00000000000001` · `7/25 → 28.000000000000004` · `14/25 → 56.00000000000001`

셋 다 **정확값인데 실수 비교로 짰으면 `≈`로 오판**됐을 케이스다. 최종 구현은 정수 산술
`R × 1000 % D === 0`. 앵커 예시도 `3/30`이 아니라 실측 검증된 `11/20`으로 교체됐다.

**교훈: 마스터 브리프의 예시도 검증 대상이다. 팀이 반증하면 그게 정상 작동이다.**

## 2) ★21일 만에 라이브 브라우저 렌더 검증 성공

07-14 이후 "픽셀 미검증"으로 남던 항목을 **이번에 실제로 뚫었다.**
`screenshot`은 여전히 타임아웃(`Browser pane is not displayed`)이지만,
**dev 서버 + DOM 실측 경로는 살아 있었다.** 375px 모바일 뷰포트에서 폼을 실제로 제출해 3분기 전부 확인:

| 분기 | 라이브 렌더 문자열 | 가로 오버플로 |
| --- | --- | --- |
| 근사(≈) | `18,240,672 ÷ 60,000,000 ≈ 30.4 %` | **0px** |
| 정확값(=) | `19,200,000 ÷ 50,000,000 = 38.4 %` | **0px** |
| 대출 0 | `0 ÷ 50,000,000 = 0 %` + 요약 `…예상 DSR은 0%입니다.` | **0px** |

**이건 QA가 "미검증"으로 남긴 바로 그 지점이다** — 계산식 행은 폼 제출 후에만 렌더되는

부수 확인: 금액 입력이 `60000000` → `60,000,000`으로 즉시 콤마 포맷됨 =
**정수 산술 판정의 대전제(digits-only 파서)가 라이브에서 실제로 성립**함을 UI로 재확인.

**함정 기록**: `form_input`/`ref` 클릭은 **좌표가 캐시돼 있어** 스크롤 후 전부 같은 지점(188,406)을
때렸다. 숫자 입력은 React state에 안 들어갔고 제출이 조용히 무시됐다.
→ 해결은 네이티브 setter + `input` 이벤트 dispatch + `form.requestSubmit()`.
**`screenshot`이 죽은 환경에서는 `ref` 클릭도 신뢰하지 마라**(좌표 캐시가 갱신 안 됨).

  근거가 부재(不在)일 때는 "현재 확인 불가"로 적고 **무효 판정은 보류**해라(§3 실사고).
- **[신규 ㋃] `screenshot`이 죽은 환경에서는 `ref` 클릭·`form_input`도 신뢰하지 마라.**
  좌표가 캐시돼 스크롤 후 엉뚱한 지점을 때리고, 숫자 입력은 React state에 안 들어가 **제출이 조용히 무시**된다.
  네이티브 setter + `input` 이벤트 + `form.requestSubmit()`이 확실하다. **하지만 브라우저 검증 자체는
  포기하지 마라 — 21일간 "불가"로 적어온 것이 실제로는 가능했다.**
